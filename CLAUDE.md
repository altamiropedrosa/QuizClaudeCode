## Project

**Quiz Claude Code** is a True/False quiz web app about Claude Code. `prd.md` (PT-BR) is the source of truth for product rules: check the referenced section before inventing behavior. All UI text and question content is in **Brazilian Portuguese**. The tone is informal, uses "você" and has light humor (PRD §9.1).

Stack: **Next.js 16** (App Router, Turbopack), React 19, TypeScript, Tailwind v4, Zod 4, Supabase (server-only), Vitest, Playwright. Next 16 differs from older versions: read `node_modules/next/dist/docs/` before using unfamiliar APIs. For example, `searchParams` is a Promise, page props use `PageProps<"/route">`, and route types are generated by `next typegen`.

In E2E runs, Supabase is not configured on purpose: the ranking page must show its "indisponível" state, and `POST /api/scores` is mocked with `page.route`.

## Architecture

- **Question bank**: `src/data/questions.json` holds the questions, typed by `Question` in `src/types/index.ts`. They are not stored in a database. Each question has exactly one `level` and one `category`, and the filter value `todas` means every category. `questionSchema` in `src/lib/validation.ts` is the contract, and `questions.test.ts` enforces it. When adding a question, keep `sourceUrl` on `docs.claude.com` and verify the statement against the current docs.
- **Match draw** (`src/lib/draw.ts`, PRD RF02) builds 3 blocks of 5 questions in `LEVELS` order. With a specific category, it fills from the level × category cell first and then from other categories of the same level. With `todas`, it takes questions round-robin across categories. `/api/questions` returns the match **with the answer key** on purpose, since the quiz is educational.
- **Scoring** (`src/lib/scoring.ts`, RF05) is shared by client and server. The client uses it for display only. `POST /api/scores` recomputes the score from `{questionId, answer, timeMs}[]` and ignores any score the client sends. A timeout is recorded as `answer: null, timeMs: 10000`.
- **Plausibility**: `validateMatch` in `src/lib/validation.ts` checks each submitted match. It requires exactly 15 unique IDs in the 5/5/5 level order and `timeMs` values in [400, 10500]. With a category filter, off-category questions are allowed only up to `5 − cellSize(level, category)` per block. The client never reports less than 400 ms, so fast players aren't rejected.
- **Ranking**: `src/lib/leaderboard.ts` (server-only) wraps all Supabase queries, including the rate limit (5 submissions per hour per salted `ip_hash`), the rank calculation and the top-20 list.
  - `/ranking` is a server component that calls `getLeaderboard` directly. `GET /api/scores` exposes the same data.
  - Leaderboards are **per match mode**: `todas` lists only matches played with "Todas".
  - Every DB error becomes a 503 `ranking_unavailable` or a friendly message. The quiz itself never depends on Supabase.
- **DB**: the schema lives in `supabase/schema.sql`. RLS is enabled with **no policies**, so only the service role (server) can access the table. Env vars (`SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `IP_HASH_SALT`) must never get a `NEXT_PUBLIC_` prefix, and an E2E test greps `.next/static` for leaks.
- **Client state**:
  - `QuizGame` runs the match as a `useReducer` state machine: loading → transition → question → feedback → … → done. `useCountdown` drives the timer with rAF + `performance.now()`.
  - The finished match goes to sessionStorage (`src/lib/matchStore.ts`, read with `useSyncExternalStore`), so `/resultado` survives a refresh.
  - `src/lib/storage.ts` wraps all browser storage in try/catch. Use it rather than touching `localStorage` directly.

## UI rules

- Colors come only from the tokens in `src/app/globals.css` (`bg surface text muted accent on-accent success danger border`, used as `bg-surface`, `text-accent`, etc.). Never hardcode colors in components.
- The light `--accent` was darkened from the PRD value to `#B84F2B` to pass WCAG AA. Text on accent must use `text-on-accent`. The axe E2E test checks both themes.
- Theme: the choice is stored in localStorage and applied in `<head>` by `themeInitScript` (`src/lib/theme.ts`) to avoid a flash. `ThemeToggle` sets `data-theme` on `<html>`.
- Style: terminal aesthetic with a `>` prompt and a mono font for titles, badges, timer, score and ranking. The `.cursor-blink` class is disabled under `prefers-reduced-motion`.
- Brand: never use Anthropic or Claude logos. The footer disclaimer in `SiteHeader.tsx` must stay on every page.
- E2E tests rely on `data-testid` attributes (`question`, `progress`, `feedback`, `block-transition`, `category-badge`, `final-correct`, …). Keep them when refactoring.

## Deploy

The app deploys to Vercel with functions in `gru1` (set in `vercel.json`) and Supabase in `sa-east-1`. Every push to `main` deploys to production at https://quiz-claude-code-gold.vercel.app.

There is a **single environment**: one Supabase project, used by production. This deliberately departs from the two environments in PRD §8.8. Preview deploys and a local `.env.local` therefore write to the real ranking, so don't point automated or E2E runs at it. Schema changes go in `supabase/schema.sql` and are applied through the SQL Editor.
